BenchBrew

The execution-verified eval factory: a policy spec and a public seed brew fresh, LLM-free task bundles on demand. A king's score means capability, not memorization.

Five lanes brewed · zero LLM in the oracle · every receipt replay-verifiable · github.com/buckZz7/benchbrew

01 Why it exists

Benchmarks decay the moment they ship: tasks leak, models memorize, kings are crowned on stale questions. BenchBrew treats a ruler as something you brew fresh, not something you publish once.

A ruler that is regenerated per evaluation and verified by replay can't be memorized into submission. New lanes are new specs — not new machinery.

04 The pipeline

One spec, one emitter, any lane. The τ² adapter is generated from the spec's own metadata — the emitted domain embeds the spec module itself, so the oracle is always the spec, never a re-translation.

05 The ruler's calibration window

Every lane targets a window, not a number. Hardening is triggered by measurement, never a schedule — re-calibrate on any spec change, harden worst-deviation-first.

0.0 weak band · 0.3–0.5 strong · ~0.85 >0.95 saturated 1.0

Compression (weak ≈ strong, both high) is the worst failure — the ruler is blind, a 4B can crown a lane. Saturation (strong ≥ 0.95) means the king is uncatchable — the ladder stalls. Floor (weak ≈ 0) is fine: it proves the lane is non-trivial. Hardening = adding a missing capability axis, not raw difficulty; a lane is done at the window.

06 Trust properties

The audit, stated plainly — the properties that make a king's score mean capability.

Zero-LLM oracle

The oracle is spec-derived DB-state predicates: valid outcomes are computed, never judged. Every rule carries a grounded source (GROUNDING.md). No LLM anywhere in the gold path or in verification.

Deterministic regeneration

(spec, seed) → identical bundle, publicly. Nothing hidden, re-runnable by anyone. The bundle hash is part of the receipt.

Fresh-lane protocol

Every battery re-emits the bundle from a fresh public seed before running. Memorizing one bundle buys nothing for the next; chain-rule seeds derive from the previous verified receipt.

Verified-only board

The board admits only receipts whose score was re-derived by replaying the recorded trajectory through the current domain code. Forged, stale, and evidence-less receipts are refused — every refusal so far has been a true refusal.

07 The arena loop

Pilsner is the scorekeeper: it consumes evals it didn't write, crowns per-lane kings, and enforces the >2% ratchet. BenchBrew is the freshness factory; τ² is the runtime.

fresh public seed→ re-emit (spec, seed)→ tau2 run→ trajectory replay-verify→ verified receipt→ board king

Independence proven live: Pilsner's own runner, τ²'s orchestrator, and BenchBrew's factory are three separate repos — Pilsner consumes domains it never wrote.
